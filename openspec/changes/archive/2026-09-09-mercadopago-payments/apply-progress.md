## Deviations

- Phase 3 uses `externalReference` as an index, not unique. The create-link use case currently uses `order_id` as the external reference, and unique would block later payment retries for the same order.
- Signature validation was implemented in `infrastructure/adapters/driver/rest/mercadopago_signature.py` instead of the driven Mercado Pago adapter because webhook protocol validation belongs at the REST boundary.
- Mercado Pago status mapping fails closed: unknown statuses map to `FAILED` rather than leaking raw provider strings inward.
- `OrderContainer` now reads Mercado Pago settings when the container is built. This keeps provider configuration explicit, but environments that use order endpoints must set `MERCADOPAGO_ACCESS_TOKEN` even before conversation integration.
- `lint-imports` now exposes real driver-to-driven transitive violations through module containers outside payment. Those were not fixed in this batch because they are unrelated to Mercado Pago and the user asked not to solve unrelated app-cycle failures.
